## 빌드와 규칙

- `node scripts/package.mjs` → `jp/build/sonar-sweep-1.1.0.zip`, `receipt.json`(파일별 SHA·소스 커밋·ZIP SHA). root `jp-build.json`, 버전 `1.1.0`, 규칙 `sonar-portal-v1`.
- 게임 소스는 HTML/CSS/설정/보드·효과/전투/랭킹/입력으로 분리했습니다. `prepare-portfolio.mjs`는 동결한 upstream에서 기계적으로 분리하는 준비 도구입니다. 이후 수정한 파일을 덮어쓸 수 있으므로 재생성은 명시적으로 검토한 경우에만 합니다.
- SDK는 `../../sdk/v1/leaderboard.js`. 2026-10-14 사용자 확정: 로그인 상태의 승리 기록은 자동 등록합니다. 비로그인 결과는 “랭킹등록을 위해 로그인 하세요”와 노란색 “로그인” 버튼을 표시하고, 로그인 완료 뒤 같은 완주 토큰으로 자동 제출합니다. 수동 기록 등록 버튼과 기기 기록 안내는 제공하지 않습니다. run token은 메모리에서만 보관하며 네트워크 실패를 로컬 기록 성공으로 대체하지 않습니다.
- 보드 3개: `sonar-sweep/easy`, `/medium`, `/hard`. 생존 `s`↓·실제 경과 `cs`↑·오폭 `m`↑, 플레이어별 최고 기록. 생존 상한 13/26/40(기본 12/24/36 + 반올림한 10% 최대 증원), 오폭 상한 10/40/99. 시간 기술값 360,000cs/TTL 3600초.
- 원본의 배속 시계는 플랫폼 서버의 실제 경과 검증과 맞지 않아 새 규칙에서 실제 경과 시계로 변경했습니다. 전투·공병 배속과 나머지 규칙/연출은 보존합니다. 숨김 중 플레이 시계·전투는 멈추며 진행 판은 등록할 수 없습니다. 결과 뒤 로그인으로 숨겨지는 것은 완료 판의 등록을 막지 않습니다.
- 자체 저장 데이터는 만들지 않습니다. `sonar-portal:` 네임스페이스를 예약하며 `sonar-rank-*` 옛 로컬 기록을 읽거나 쓰지 않습니다. 진행 판 복원 기능은 없습니다.
- iframe 최소 640×900, aspect 1.25, 방향 any. 터치 깃발 모드·길게 누르기를 지원합니다. 실제 플레이와 최소 뷰포트는 플랫폼 준비 하네스로 검증합니다.
